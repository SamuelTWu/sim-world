## Phase C: Autonomy (Needs, Decisions, Flow Fields, Sense Handoff)

Every autonomous pixel runs one loop: **update needs -> decide -> travel -> arrive (by sensing) -> act -> update -> decide**. The loop is data-driven and species-agnostic: a worker, a bee, a Dune Worm, Santa, a boat, a bicycle and a mobster are all blueprints plus task definitions. **No `.py` file may contain a species, job or vehicle name.** If an archetype needs Python, a generic primitive is missing: add the primitive, not a special case.

Core design rules for this phase (apply to every item):

1. **Event-driven, not scanning.** A pixel costs nothing per tick while it sleeps (waiting on a timer, idle with backoff, or travelling along a field). Needs are lazy values with scheduled threshold wakes. Decisions run from a wake queue. The task runner touches only pixels whose phase needs it.
2. **Fields are shared.** Flow fields are keyed by goal, movement profile and reach, never by entity. N pixels with the same goal share one field.
3. **Fields get you to the neighborhood, senses finish the job.** The movement goal is a predicate ("an action precondition is satisfiable"), not a tile. Arrival is decided by a sense query, not by reaching a source tile.
4. **Static goals use fields, dynamic goals use influence maps.** Nothing in this phase may path toward a pixel the pixel's scope cannot know about (fog and stealth rules still apply).
5. **Stability is mandatory.** Hysteresis, commitment and local separation (C.2.4, C.7.2) are part of the implementation, not tuning extras. Each has a test that fails if it is removed.
6. **One walkability truth.** Flow fields, pixel movement and projectiles all call the same passability functions from `world/collision.py`.

Existing pieces to reuse (confirm names): `entity/system/task.py`, `needSystem.py`, `decisionSystem.py`, `memorySystem.py`, `attributeSystem.py`, `behavior/behavior.py`, `behaviorManager.py`, `simContext.py`, `stimulus.py`, `entity/system/scheduler.py` (G.4), `world/collision.py` (`tile_blocked`, `structure_blocks`), `StructureManager` (`caps`, `by_chunk`, `occupancy`), `server/interest.py` (`SpatialGrid`), `world/chunks.py`, `command/visibility.py` (`can_see`, `REVEALS`), `server/fog.py` (`is_visible`), `entity/inventory.py`, `entity/objects.py` (`spawn`, `transfer`, `drop`, `launch`), `world/statehash.py`, server stats.

Dependencies: G.4 (scheduler), G.6 (`state_hash`), B.1 and B.3 (`structure_blocks`, `tile_blocked`, `caps`), 13.1 (`Fog`). C.4 to C.9 can start once B.3 is done. The `throw` behavior in A.2.4 becomes a task definition once C.3 exists.

### C.1 Data model

- [ ] C.1.1 **Task definitions.** Create `entity/taskTypes.json` (same role as `projectileTypes.json`) and extend the loader in `entity/system/task.py`. Entry shape:
  ```json
  "fish": {
    "requires": {"attrs": ["extract"], "tags_any": []},
    "needs": {"hunger": 0.8},
    "goal": {"kind": "tile_tag", "tag": "water", "reach": {"param": "extract.range", "default": 0}},
    "arrive": {"sense": {"tile_tag": "water"}, "within": 1},
    "act": [{"step": "extract", "target": "arrival", "ticks": 60}],
    "satisfies": {"hunger": -0.3},
    "priority": 1, "interrupt_level": 2, "min_commit": 40, "cooldown": 20,
    "timeout": 600, "search_ticks": 80, "chase": false, "on_fail": "penalize"
  }
  ```
  `requires` is checked against the pixel's unlocked attributes and tags (never names). `act` steps name existing action functions (`extract`, `consume`, `produce`, `spawn`, `transfer`, `drop`, `place`, `build`, `launch`, `strike`) through a dict `ACT_STEPS = {name: fn}`; each fn returns `"ok" | "retry" | "fail" | "done"`. Unknown task, step, goal kind or need name is a load-time error. A `Task` runtime record is a plain dict (C.1.4).
- [ ] C.1.2 **Goal descriptors.** Define in `entity/system/task.py`; `goal.kind` is one of: `tile_tag {tag, reach}`, `structure_tag {tag, reach}`, `structure_cap {cap, reach}`, `pixel_tag {tag, reach}`, `point {x, y}`, `zone {x, y, r}`, `layer {name, min}` (C.6), `home`, `owner`. `reach` is an int or `{"param": "<attr.param>", "default": n}`, read from the acting pixel's attribute parameters at decision time (this is how "stand next to the water if you have a rod, stand in the water if you do not" is expressed with no special case). `goal_key(goal, reach)` returns a hashable tuple used for field keys, memory and blacklists.
- [ ] C.1.3 **Locomotion profiles.** Create `world/locomotion.json`: `{"walker": {"passable_tags": [...], "blocked_tags": [...], "tile_cost": {"sand": 12, "road": 7, "default": 10}, "diagonal": true, "doors": true}, ...}`. Costs are small integers (10 = one orthogonal step). Blueprint field `locomotion: "<profile>"`; default `walker`. Add `passable(sim, profile, tx, ty, mover=None) -> bool` in `world/collision.py`. It wraps `tile_blocked`, `structure_blocks` (so doors and owner-only gates behave identically everywhere) and the profile's tile tags, and returns `False` for out-of-bounds. The accessor `profile_of(entity) -> str` is the only way callers get a profile, so a carrier or vehicle override can be added later without touching callers. No other locomotion code.
- [ ] C.1.4 **Pixel runtime state.** `entity.ai` is a plain dict (ints, floats, strings, lists, dicts only): `{"task": None|{...}, "pinned": None|{...}, "needs": {name: {"v": f, "t": int, "rate": f, "active": bool, "seq": int}}, "next_eval": int, "commit_until": int, "cooldown": {task: until}, "fail": {goal_key_str: {"n": int, "until": int}}, "nav": None|{...}, "mem": [...]}`. Created lazily only for blueprints with `autonomy != "none"`. Included in the pixel's serialized state (C.12). Not part of `replication.entity_state`.
- [ ] C.1.5 **Needs as lazy values.** Blueprint `needs: {"hunger": {"start": 0.2, "rate": 0.0005, "min": 0, "max": 1, "hi": 0.6, "lo": 0.3, "curve": 2.0, "critical": 0.9}}`. Value is computed on read: `need_value(e, name, tick) = clamp(v + rate * (tick - t))`; nothing ticks per pixel. `set_need(e, name, delta_or_value, tick)` and `set_rate(e, name, rate, tick)` first fold the elapsed time into `v`/`t`, then apply the change. `AttributeSystem` calls `set_rate` when a modifier changes (for example temperature raising energy use). Periodic behavior is just a need with a positive rate that is reset on success (Santa's "deliver" urge, a bee's "return to hive" urge); no timer-specific code.
- [ ] C.1.6 **Threshold wakes.** After every `set_need`/`set_rate`, compute the tick where the need crosses `hi` (if rising and currently inactive) or `lo` (if falling and active) or `critical`, and call `scheduler.schedule(tick, "need_wake", pixel_id, need, seq)`. Increment `need.seq` on every change; a `need_wake` whose `seq` is stale is ignored (the scheduler cannot cancel). A valid wake flips `need.active` (Schmitt trigger: active above `hi`, inactive below `lo`, unchanged between) and calls `wake(e, reason="need")`.
- [ ] C.1.7 **No-species guard.** `check_task_data.py` greps every `.py` under `entity/`, `world/`, `server/`, `command/` for a banned-word constant list defined in the check itself (`wolf sheep cow worker miner bee worm santa boat bike bicycle mobster fish` and similar) and fails on any hit outside comments/strings of existing blueprints. Also tests: schema validation, every unknown-name load error, `goal_key` stability, need math (lazy value, rate change mid-flight), threshold wake scheduling (including a stale `seq` being ignored), JSON and `to_dict` round trip, no pygame. Print the check count.

### C.2 Decision system (utility, hysteresis, commitment)

- [ ] C.2.1 **Wake queue, not a scan.** `DecisionSystem` keeps no per-tick loop over pixels. `wake(e, reason)` calls `scheduler.schedule(tick, "decide", id, ai_seq)`; a stale `ai_seq` is ignored. Wake reasons: `arrive`, `task_end`, `need`, `damage`, `inventory`, `stimulus`, `command_cleared`, `memory_expired`, `idle`, `interrupt`. Per tick at most `MAX_DECISIONS_PER_TICK` run, in `(due_tick, id)` order; the rest slip one tick (counter `decisions_deferred`). Initial `next_eval = tick + (id % IDLE_EVAL_TICKS)` so a freshly spawned population is spread out without RNG. An idle pixel that decides "nothing" reschedules itself with backoff `IDLE_EVAL_TICKS` doubling up to `IDLE_EVAL_MAX` (defaults 20 and 160), reset by any wake. A pixel inside its `commit` window or in TRAVEL/ACT is never re-evaluated except through an interrupt.
- [ ] C.2.2 **Candidate generation.** `candidates(e, tick)`: tasks whose `requires` are met, not in `ai.cooldown`, not blacklisted in `ai.fail` for the same `goal_key`, and whose goal passes the reachability filter (C.5.3). Cap at `MAX_CANDIDATES` (default 12), ordered by static `priority` then name. Pure function of pixel data and world state.
- [ ] C.2.3 **Utility.** `score(t) = base(t) + sum(urgency[n] * t.needs[n]) - TRAVEL_K * travel_ticks - fail_penalty + bias[t]`. `urgency[n] = 0` if the need is inactive, else `((v - lo) / (1 - lo)) ** curve`. `travel_ticks` comes only from an already-warm field via `FieldManager.peek_cost` or, if cold, from the coarse chunk estimate (C.5.4); scoring must never build a field. `bias` is an optional blueprint map `{task: float}` (personality). No randomness: ties resolve by task name order. Scores clamp at 0 and a pixel with no positive score goes idle.
- [ ] C.2.4 **Hysteresis and commitment (all four are required).**
  1. *Schmitt thresholds* on needs (C.1.6): no flapping around a single threshold.
  2. *Commitment window*: after choosing a task, `ai.commit_until = tick + task.min_commit`. Inside the window only an interrupt with `level >= task.interrupt_level` may preempt (C.2.5).
  3. *Switch margin*: the incumbent task gets `+COMMIT_BONUS` (default 0.25 of its score) decaying linearly to 0 over `COMMIT_DECAY_TICKS` (default 100). A challenger replaces it only if `challenger > incumbent * (1 + SWITCH_MARGIN) + SWITCH_EPS` (defaults 0.2, 0.01).
  4. *Failure memory*: a failed task writes `ai.fail[goal_key] = {"n": n+1, "until": tick + BLACKLIST_BASE * 2**min(n, 4)}`; `fail_penalty` and candidate exclusion read it, and `n` decays on success. After any task ends, `ai.cooldown[task] = tick + task.cooldown` so the same task is not re-picked instantly.
- [ ] C.2.5 **Interrupts.** `INTERRUPT_LEVELS = {"idle": 0, "need": 1, "stimulus": 2, "damage": 3, "critical_need": 3, "command": 4}`. A task's `interrupt_level` is the minimum level that may preempt it. `interrupt(e, level, reason)` ends the task with reason `interrupted` through `end_task` (C.3.4) and wakes the pixel. `critical` need crossings (C.1.6) emit `critical_need`; `EventBus` damage events emit `damage`; `stimulus.py` emits `stimulus` only for stimuli matching the pixel's `Filter`/`Aggro` tags.
- [ ] C.2.6 **Player pin.** A player command sets `ai.pinned` (C.10) and `DecisionSystem` skips pinned pixels. Pin ends on task done, task fail, a new command or `stop`. Pinned tasks use the same task runner as autonomous ones.
- [ ] C.2.7 Test `check_decision_hysteresis.py`: (a) two tasks whose raw scores oscillate +/-10% around each other produce 0 switches over 2 000 ticks; (b) a sustained 40% swing switches exactly once, and not before `commit_until`; (c) a need hovering between `lo` and `hi` never toggles `active`; (d) interrupts below `interrupt_level` are ignored, above it preempt; (e) failure blacklist excludes the goal, then expires; (f) 5 000 idle pixels cost zero decisions per tick between wakes (assert counter); (g) `MAX_DECISIONS_PER_TICK` honored; (h) same seed twice gives equal `state_hash`. Removing any of the four hysteresis mechanisms must fail at least one case.

### C.3 Task runner

- [ ] C.3.1 `TaskRunner` in `entity/system/task.py`. Phases: `TRAVEL -> ARRIVE -> ACT -> UPDATE` with side phases `SEARCH` and `END`. Stored in `ai.task = {"name", "goal_key", "phase", "started", "deadline", "target": ref|None, "step": i, "wait_until": tick, "arrive_r": n}`. The runner is entered through scheduled callbacks (`task_step`, `act_done`, `search_done`) and through arrival events from movement (C.7.1); it never loops over all pixels. Add `task_step`, `act_done`, `decide`, `need_wake` to the scheduler's callback dict.
- [ ] C.3.2 **ACT.** Runs `task.act[i]` through `ACT_STEPS`. Steps with a duration (`ticks`) schedule `act_done` and let the pixel sleep (fishing wait, production, attack cooldown). Before every step, re-validate: target alive, `visibility.can_see`, still within the step's range, the pixel's attribute still unlocked and inventory preconditions (use the same checks as the corresponding command). Failure to validate goes to SEARCH (target lost) or `end_task("invalid")` (pixel can no longer act).
- [ ] C.3.3 **UPDATE.** On success: apply `satisfies` to needs through `set_need`, clear matching `fail` entries, emit the action's event through `EventBus`, and let the world change do the rest. Follow-up behavior is not scripted: a pixel that caught an item now has `inventory_load` or `holding_tag:<tag>` pressure (a derived need computed by `AttributeSystem`), so `pickup`/`deposit` tasks score high through normal utility. The "fish -> pick up -> store" chain is a result of data, not of a chain table.
- [ ] C.3.4 **`end_task(e, reason)`** is the only way a task ends. Reasons: `done`, `fail`, `timeout`, `interrupted`, `invalid`, `not_found`, `stuck`, `no_capacity`, `unreachable`. It releases the field handle (C.4.6), clears `ai.task`, sets cooldown/failure memory per C.2.4, cancels nothing in the scheduler (stale callbacks are ignored by `ai_seq`) and calls `wake(e, "task_end")`. Every deadline (`timeout`) is a scheduled callback, not a per-tick check.
- [ ] C.3.5 Test `check_task_runner.py` with data only: fish -> pickup -> deposit into a storage structure, asserting order and resource totals (use the storage transfer rollback from B.4.7); `timeout` ends travel; stale scheduler callbacks after `end_task` are ignored; every `end_task` reason releases the field handle (refcount returns to the baseline).

### C.4 Flow fields

- [ ] C.4.1 Create `world/flowfield.py` (pure, no pygame, no server imports):
  ```python
  @dataclass(frozen=True)
  class FieldKey: goal: tuple; profile: str; reach: int; scope: str|None
  class FlowField:
      key: FieldKey; cost: dict[(cx,cy), array('H')]   # CHUNK_SIZE*CHUNK_SIZE, INF=65535
      sources: list; frontier: list[list]; refs: int; last_used: int; epoch: int
      def sample(tx, ty) -> int|None                  # None = not reached yet
      def step_dir(tx, ty, passable) -> (dx,dy)|None   # lowest-cost passable neighbor
  class FieldManager:
      def acquire(key, sim) -> Handle; def release(handle); def peek_cost(key, tx, ty) -> int|None
      def expand(budget_nodes) -> int; def on_tile_changed(tx, ty); def stats() -> dict
  ```
  Algorithm is Dial's bucket-queue Dijkstra over integer costs (profile `tile_cost`, diagonals 14 with no corner cutting through impassable cells). Cost arrays are allocated per chunk on first touch. Neighbor order is fixed (N, E, S, W, then NE, SE, SW, NW) and ties break on the lowest `(dx, dy)` tuple, so `step_dir` is deterministic.
- [ ] C.4.2 **Demand-driven, budgeted expansion.** A field is created empty and expands from its sources outward. `FieldManager.expand(budget)` runs once per tick after `SystemRunner` and before movement, processing at most `FIELD_NODES_PER_TICK` nodes (default 4 000) round-robin over fields that have unreached subscribers, most subscribers first. A field stops expanding when every subscriber tile has a finite cost and the frontier cost exceeds `max_subscriber_cost + FIELD_MARGIN`. Never flood to world size. Counter `field_expansions`.
- [ ] C.4.3 **Pending behavior.** A pixel whose tile is unreached by its field (`sample` is `None`) is `PENDING`: it holds position (or uses direct steering toward the nearest source chunk from C.5.4) for up to `FIELD_WAIT_TICKS` (default 40), then ends with `unreachable`. It never waits on a field with no remaining frontier (that means no path: end immediately).
- [ ] C.4.4 **Source resolution.** `resolve_sources(sim, goal, reach, scope) -> list[tile]` returns the passable tiles (for the profile) within Chebyshev distance `reach` of each matching target; with `reach = 0` the matching tiles themselves must be passable for the profile, otherwise the goal has no sources and the task is unavailable (a non-swimmer cannot "stand in water"). Matching uses indexes, never world scans: add `world/tagindex.py` (`tag -> chunk -> set(tile)`) fed by world generation and by the single world modification function, and use `StructureManager.caps`/`by_chunk` plus structure tags for structure goals. `point`/`zone` goals produce their tiles directly. `layer` goals resolve through C.6.
- [ ] C.4.5 **Invalidation by rebuild, not repair.** `FieldManager.on_tile_changed(tx, ty)` is called from the world modification function, `StructureManager._register/_unregister`, and door toggles (B.4.6). It marks the chunk dirty. At most once per `FIELD_REBUILD_COOLDOWN` ticks (default 10, so a battle of edits is batched) every field whose computed region includes a dirty chunk starts a rebuild into a back buffer (`epoch + 1`); sampling keeps using the front buffer until the rebuild covers all subscribers or completes, then buffers swap. At most one rebuild in flight per field (further changes set an `again` flag). Reason: incremental repair of cost *increases* is incorrect with simple chunk resets. Rebuilds are demand-limited by C.4.2. Counter `field_rebuilds`.
- [ ] C.4.6 **Subscriptions and eviction.** `acquire` returns a handle and increments `refs`; `release` decrements. Fields with `refs == 0` live for `FIELD_TTL_TICKS` (default 400), then are dropped. `MAX_FIELDS` (default 256): evict least-recently-used zero-ref fields first; if all are in use the request fails and the task ends `no_capacity` (counter). Field keys for moving or quantized goals use `POINT_QUANT` (default 4 tiles) so many pixels share a key.
- [ ] C.4.7 **Step-time guard.** `step_dir` receives a `passable` callable and never returns a blocked tile. If the best neighbor is blocked it tries the next-lowest strictly-lower-cost neighbor; if none exist the pixel is stuck (C.7.3). The field is a hint; the guard is what keeps a stale field harmless.
- [ ] C.4.8 Test `check_flowfield.py`: (a) on 20 seeded random grids, field costs equal a plain reference Dijkstra; (b) wall placement re-routes subscribers within the rebuild budget; (c) door open/close changes the route; (d) walker vs swimmer fields differ on the same map; (e) reach dilation (`reach` 0 vs 1) gives different sources; (f) `FIELD_NODES_PER_TICK` is never exceeded and a field covering 200 subscribers expands only to their radius; (g) 100 pixels sharing a goal create exactly one field; (h) eviction and `MAX_FIELDS`; (i) `step_dir` tie order is stable across runs.

### C.6 Dynamic goals: influence layers

- [ ] C.6.1 Create `entity/system/influence.py` and `entity/influenceTypes.json`: `{"prey": {"match": {"tag": "..."}, "scope": "owner"|"tag:<identity_tag>", "decay": 0.97, "decay_every": 20, "min": 0.05}, ...}`. State is sparse: `layers[name][scope][chunk] -> float`. A layer has no knowledge of any species; `match` is a tag filter.
- [ ] C.6.2 **Deposits come from sensing, not from scanning.** When any pixel completes a sense query (C.8.1) in scope, matching results deposit `+DEPOSIT` into the chunk of each result, for that pixel's scope(s). Memory `seen` records may also deposit. A scope never receives deposits for entities its members could not see (reuse `can_see`/fog). No world-wide sampling loop.
- [ ] C.6.3 **Decay** is scheduled per nonzero chunk (`influence_decay` callback), multiplies by `decay`, and deletes entries below `min`. Cost is proportional to nonzero chunks.
- [ ] C.6.4 **`layer` goals.** `resolve_layer(sim, e, goal) -> zone`: choose the highest-valued chunk (value >= `goal.min`) within `LAYER_SEARCH_CHUNKS` of the pixel (ties by chunk coordinate), return a `zone` goal centered on the chunk center with radius `ZONE_R`, quantized by `POINT_QUANT`. Retarget hysteresis: the task keeps its current zone until its value falls below `min`, or another chunk exceeds it by `RETARGET_MARGIN` (default 0.5 relative) and at least `RETARGET_TICKS` (default 40) have passed. This is how "the battle moved west" or "the herd drifted" is followed without flapping.
- [ ] C.6.5 Test `check_influence.py`: a drifting target group retargets hunters only after the margin and interval; no retarget oscillation under noisy values (count zone switches); decay empties the layer; a scope with no observers gets no deposits (no information leak, tested next to the fog leak check from 13.3.5); layer state saves and loads.

### C.7 Movement integration and local separation

- [ ] C.7.1 **Navigation state.** `ai.nav = {"field": handle_id, "stuck": n, "last": [tx, ty], "last_tick": t}`. Locate how movement currently advances a pixel toward a move target (see B.3.3) and replace that path: the existing `move` command becomes a pinned task with a `point` goal (C.10.1), so there is one movement path, not two. Movement for a TRAVEL pixel each tick: `step_dir` from the field, desired velocity = direction * `speed`, where `speed = Speed attribute * profile step multiplier * tile speed modifier`. No type-specific speed code.
- [ ] C.7.2 **Light local separation (required).** Steering term computed after all pixels have chosen a flow direction, in two phases (compute all desired velocities from a snapshot of positions, then commit) so results never depend on iteration order. For each moving pixel:
  - Fast path: if the pixel's spatial-grid cell contains only itself (and no neighbor cells within `SEP_RADIUS`), skip separation entirely (counter `sep_skipped`).
  - Otherwise take up to `SEP_MAX_NEIGHBORS` (default 8) nearest pixels within `SEP_RADIUS` (default 0.6 tile) from `SpatialGrid`, ordered by `(distance, id)`, optionally filtered by blueprint `separation.group` (`"all" | "tag:<t>" | "none"`).
  - `sep = sum((p - q) / max(d*d, EPS))`, magnitude capped at `SEP_WEIGHT * speed` (default 0.35).
  - Final velocity = normalize(flow_dir * speed + sep), magnitude `speed`.
  - If the resulting next tile is not `passable` or its field cost exceeds the current tile's cost by more than `SEP_SLACK`, discard the separation term for this tick and use the pure flow direction.
  - Scale `SEP_WEIGHT` down to 0 when the pixel is in a corridor (2 or fewer passable neighbor tiles) so separation cannot deadlock chokepoints and doorways.
  Blueprint `separation: {"radius", "weight", "group"}` is data: swarms can use a tight radius with group `tag:swarm`, a convoy can use `none`. Pixels have no hard collision; separation is steering only.
- [ ] C.7.3 **Stuck detection.** Every `STUCK_CHECK_TICKS` (default 20), scheduled per moving pixel, compare tile and tick to `ai.nav.last`. If displacement is below `STUCK_EPS`: resample the field and increment `nav.stuck`; at `STUCK_FAIL` (default 3) call `end_task("stuck")`, write a `blocked` memory (C.9) and blacklist the goal key (C.2.4).
- [ ] C.7.4 **Arrival spreading.** Arrival radius for a group goal is `arrive_r = 1 + isqrt(group_n) // 2` (group size from the shared field handle count), so a box-selected group stops in a disc around the goal instead of stacking on the source tile. Single pixels use `arrive_r = 1`.
- [ ] C.7.5 Test `check_separation.py`: (a) 200 pixels sent to one goal: max pixels per tile at arrival is lower than with `SEP_WEIGHT = 0`; (b) no separated pixel ever enters an impassable tile; (c) 50 pixels pass a 1-wide gate in bounded ticks with no deadlock; (d) a lone pixel runs with zero separation work (counter); (e) neighbor cap honored; (f) two runs give equal `state_hash` (commit phase is order independent); (g) `separation.group = "none"` pixels ignore each other.

### C.8 Sense handoff and arrival

- [ ] C.8.1 `sense(sim, e, filter, radius=None) -> list[ref]` in `entity/system/sense.py` (reuse the existing Sight/Filter code; inspect first). Sources: pixels from `SpatialGrid`, structures from `occupancy`/`by_chunk`, tiles from the tag index. Applies `visibility.can_see` (stealth and `REVEALS`), the pixel's sight radius, the filter (tile tag, pixel tag, owner/ally/enemy, resource), and returns results sorted by `(distance, kind_rank, id)`; refs are kind-tagged (`("p", id)`, `("s", id)`, `("t", tx, ty)`). Line of sight stays off until the fog LOS flag exists (13.2.2). Each call bumps `sense_queries` and feeds C.6.2.
- [ ] C.8.2 **Arrival is a predicate.** While TRAVEL, the pixel is not polled. Arrival is checked when (a) the field cost at its tile reaches 0 (it is on a source tile), or (b) it enters within `SENSE_PREPOLL_COST` (default 60 = about 6 tiles) of the goal, then every `ARRIVE_POLL_TICKS` (default 4) via a scheduled `task_step`. If `task.arrive` holds (the sense query finds at least `count_min` matches within `within`), bind `task.target` to the nearest result and enter ACT. This gives Sight real value: a pixel with long sight stops the moment it sees its target; one with short sight walks closer or searches.
- [ ] C.8.3 **SEARCH.** Reaching a source tile without a valid target starts SEARCH for `task.search_ticks`: move to random nearby passable tiles drawn from the sim's seeded RNG (consumed in sorted-id order via the scheduler's deterministic ordering) or to a `zone` of radius `SEARCH_RADIUS` around the goal, sensing every `ARRIVE_POLL_TICKS`.
